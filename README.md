# DevRelSurvey

[![.NET 8](https://img.shields.io/badge/.NET-8.0-purple)](https://dotnet.microsoft.com/)
[![React 18](https://img.shields.io/badge/React-18-blue)](https://react.dev/)

Веб-приложение для визуализации результатов ежегодного опроса узнаваемости и привлекательности ИТ-компаний в Ростове-на-Дону и Ростовской области от сообщества [RndTech](https://rndtech.pro/).

## 📊 О проекте

DevRelSurvey — это платформа для анализа данных о восприятии ИТ-компаний на рынке труда Ростова-на-Дону на основе ежегодных опросов ИТ-сообщества.

### Ключевые возможности

- 📈 **Интерактивная визуализация данных** — графики узнаваемости и привлекательности компаний
- 🔍 **Гибкая фильтрация** — по городам, специальностям, опыту, языкам программирования и другим параметрам
- 📅 **Сравнение по годам** — отслеживание динамики показателей компаний
- 📱 **Адаптивный дизайн** — поддержка мобильных устройств
- ⚡ **Высокая производительность** — предзагрузка данных в память для мгновенного отклика

### Компоненты системы

#### 1. RndTech.DevRel.Database
Слой доступа к данным на базе Entity Framework Core:
- **Модели сущностей**: Company, Interviewee, CompanyAnswer, Language, CommunitySource
- **Конфигурации EF**: типизированные конфигурации для каждой сущности
- **DbContext**: SurveyDbContext для работы с MySQL через Pomelo.EntityFrameworkCore.MySql

#### 2. RndTech.DevRel.App
Основное веб-приложение с архитектурой на базе минималистичного CQRS:

**Backend компоненты:**
- **Query Handlers**: обработчики запросов для получения данных
- **Data Provider**: `IntervieweesPreloadedDataProvider` для предзагрузки данных в память
- **Filters**: маппинг и обработка фильтров от клиента

**Frontend компоненты:**
- **CompaniesPage**: главная страница с картой и таблицей компаний за выбранный год
- **AudienceMatrixPage**: компании по восьми измерениям аудитории, точные доли и знаменатели
- **SamplePage**: состав выборки по годам
- **FilterPanel**: панель фильтров с пресетами
- **FilterDrawer**: на ширине меньше 1224 px все фильтры доступны в панели с черновиком; «Показать результаты» применяет правки, «Отмена» их отбрасывает. Год, компании, состав выборки и «О данных» доступны на всех экранах; изменение ширины сохраняет состояние.

#### 3. RndTech.DevRel.Importer
Консольная утилита для импорта очищенных данных опроса в БД. Сейчас поддерживает только CSV 2022 года; имя файла `2022.csv` и пустая строка подключения заданы в коде (`2022/Importer.cs`), аргументов командной строки нет.

## 🚀 Быстрый старт

### Требования

- .NET 8 SDK

- MariaDB или MySQL со схемой и данными; для локальной работы подойдёт синтетический `tests/smoke/seed.sql` (только MariaDB, см. [CONTRIBUTING.md](CONTRIBUTING.md#smoke-стенд-с-mariadb))

### Локальная разработка

1. **Клонируйте репозиторий:**
```bash
git clone https://github.com/RndTechCommunity/DevRelSurvey.git
cd DevRelSurvey
```

2. **Настройте переменные окружения:**
```bash
# Для локальной разработки
export DEVRELAPP_CONFIG_DATABASE="Server=localhost;Database=devrel;User Id=user;Password=password"
```

3. **Восстановите зависимости:**
```bash
dotnet restore
cd src/RndTech.DevRel.App/ClientApp
npm ci
cd ../../..
```

4. **Запустите backend и frontend в двух терминалах:**
```bash
# Backend (API на http://localhost:29500), корень репозитория
ASPNETCORE_ENVIRONMENT=Development dotnet run --no-launch-profile --project src/RndTech.DevRel.App

# Frontend, src/RndTech.DevRel.App/ClientApp
npm start
```

Интерфейс будет доступен по адресу `http://localhost:44422`: dev-сервер Vite проксирует `/api` на backend `http://localhost:29500`. Собранный фронтенд backend отдаёт на 29500 только из результата `dotnet publish` или в Docker-образе.

### Docker

**Сборка образа:**
```bash
docker build -t devrel-survey .
```

**Запуск контейнера:**
```bash
docker run -p 29500:29500 \
  -e DEVRELAPP_CONFIG_DATABASE="connection_string" \
  devrel-survey
```

### Страница «Матрица аудиторий»

Четыре поля «Компании → Группировать по → Колонки → Показатель» занимают один ряд на desktop. Компании общие с картой; пустое ограничение
означает все имена всех лет, «Популярные» выбирает исторические 29. Колонки выбираются из полного каталога
профессий, языков, возрастов, городов, образования, грейдов, участия в сообществе или источников информации.
Начальный набор — до шести самых многочисленных групп текущего года/фильтра; ручной набор сохраняется,
включая неизвестные и временно пустые значения. Очистка колонок означает ни одной, «Начальные группы» возвращает автонабор.

Общий фильтр действует через AND в каждой колонке. «Выборка: N» рядом с годом берётся из того же ответа,
что матрица; N над колонкой — число людей в ней. В ячейках показан только процент; точные отметки и число
ответов о компании доступны в подсказке по наведению, фокусу и касанию. Escape закрывает подсказку.
Языки и источники пересекаются, суммировать N нельзя. Ноль отличается от отсутствия данных.
Текст ячеек всегда чёрный, шкала общая для показанных значений и обеих тем. Вертикально прокручивается
страница, горизонтально — таблица; полные подписи и все колонки остаются доступны.

По умолчанию строки идут по имени. Клик, Enter или Space на заголовке сортирует по колонке, повтор меняет
направление. Новая численная колонка начинается с убывания, имя — с возрастания; отсутствующие значения
остаются в конце. Сортировка использует исходную долю до округления, при равенстве — исходное имя.

Матрица показывает один год: сохранённое сравнение доступно на остальных страницах. В 2019 «Рекомендуют»
временно заменяется на «Хотят работать» с пояснением; сохранённый показатель возвращается для других лет.
Показатель, компании, сортировка, тема и ширина не вызывают новый batch. Новый год, фильтр, измерение или набор
колонок вызывают один запрос; загрузка и ошибка скрывают старую матрицу, её числа и подробности.

Ссылки записываются в формате `v=2`: поле `matrix` содержит JSON с `groupBy`, `groupValues`, `metric`, `sort`.
`groupValues:null` — автонабор, `[]` — ни одной колонки. Все настройки сохраняются при переходах между страницами,
через «Дублировать» и Back/Forward; прежние v1 и legacy-ссылки читаются явно. При превышении 8000 символов
ссылка не записывается и не открывается, появляется предупреждение, состояние в памяти не обрезается.
Старые matrix.sort=base (asc/desc) читаются как name asc без потери остальных настроек; новые ссылки base не записывают.

### Добавление нового фильтра

1. Создайте модель запроса в `Model/Queries/`
2. Реализуйте обработчик в `Implementation/QueryHandlers/Filters/`
3. Зарегистрируйте обработчик в `Program.cs`
4. Добавьте endpoint в `IEndpointRouteBuilderExtensions.cs`
5. На фронтенде добавьте справочник в `FilterOptions` и `getFilterOptions` (`ClientApp/src/api/`), поле — в `features/filters/model.ts` (тип, исходный фильтр, разбор ссылки, сравнение в `sameFilter`: массивы перечислены в `FILTER_ARRAY_KEYS`) и `features/filters/FilterPanel.tsx`

### Импорт данных нового года

1. Создайте папку с годом в `src/RndTech.DevRel.Importer/`
2. Реализуйте классы для чтения формата данных
3. Создайте маппинг в Entity модели
4. Укажите в коде путь к файлу и строку подключения: аргументов командной строки импортёр не принимает

## 📊 API Endpoints

### Получение данных компаний
```
POST /api/results/known-and-wanted
Content-Type: application/json

Body: UserFilter (фильтры для выборки)
```
Возвращает информацию об узнаваемости и привлекательности компаний.

### Получение метаданных
```
POST /api/results/meta
Content-Type: application/json

Body: UserFilter (фильтры для выборки)
```
Возвращает информацию о составе выборки.

### Матрица аудиторий

`POST /api/results/audience-matrix`, `Content-Type: application/json`:

```json
{
  "year": 2022,
  "filter": {"cities":[],"educations":[],"languages":[],"professions":[],"experiences":[],"ages":[],"isCommunity":null},
  "groupBy": "languages",
  "groupValues": ["JavaScript", "TypeScript"]
}
```

Ответ содержит `year`, `groupBy`, `baseRespondentCount` (число людей общего фильтра за этот год),
`baseCompanies` (обычные `CompanyModel[]` базы), `companyNames` (исходные имена всех компаний с ответами во всех годах),
`availableValues` и `columns`. Элемент каталога — `{value, label, respondentCount}`; колонка дополнительно содержит
`companies: CompanyModel[]`. Каталог охватывает все предзагруженные годы, его counts — только текущие год/фильтр.
Он включает редкие города и значения с нулевым текущим count, без ограничения top-N.

Каждая колонка — **общий фильтр AND значение группировки**, включая уже ограниченное измерение.
Знаменатель доли компании — её `selectionCount`, число строк ответов, а не `respondentCount` колонки.
Отсутствующая компания не превращается в запись с нулями. Доли и исторические формулы `CompanyModel` сохранены.

| `groupBy` (точная строка) | Значение колонки |
|---|---|
| `professions`, `cities`, `educations` | Исходное имя |
| `languages` | Исходное имя; JavaScript и TypeScript включают историческое `JavaScript / TypeScript` |
| `ages` | Строка нижней границы пятилетия, например `"60"` для 60–64; каталог не ограничен возрастами UI |
| `experiences` | Исходный грейд; JSON `null` — «Не указан», `""` — отдельное «Пустое значение» |
| `isCommunity` | `"true"` / `"false"`, признак «митапы ИЛИ сообщество» |
| `communitySources` | Исходное имя источника |

Языки и источники могут пересекаться: N колонок не суммируется. Каталог языков заменяет combined двумя отдельными
опциями; явно переданный `JavaScript / TypeScript` означает точное историческое значение.
Пустая строка сохраняется, строки не обрезаются и не нормализуются. Правильное неизвестное значение возвращает N=0 и `companies: []`.

`groupValues: null` или отсутствие поля выбирает до шести положительных групп: count по убыванию, затем исходное value ordinal
по возрастанию (null перед строками). `[]` возвращает ноль колонок и сохраняет базу/каталог. Явный массив сохраняет порядок;
повторы удаляются по первому появлению. Каталог упорядочен ordinal (null первым), возраст — по нижней границе.

Ограничения нового route:

- Внешний `year` — целое 2019–2022; вложенный `filter.year` игнорируется, как в старом mapper.
- `filter` и все шесть его массивов обязательны: только строки без null, суммарно не более 256 элементов.
  Пустые массивы означают все. `isCommunity`: «Да» → true, «Нет» → false, другое или null — без ограничения.
- `filter.ages` имеет форму `20 - 24 лет`: две цифры, начало кратно пяти, конец на четыре больше.
  Значения колонки `ages` — канонические десятичные Int32, кратные пяти, без переполнения верхней границы.
- Не более 256 выбранных колонок до удаления повторов; сам каталог этим лимитом не обрезается.
  Null-элемент разрешён только в `experiences`.
- Тело не более 1 МиБ, включая chunked: превышение — 413. Неверный JSON/тип/значение — 400,
  неверный Content-Type или неподдерживаемый/пустой charset — 415. Поддерживаемый charset принимается
  с кавычками и без них. Ошибки возвращаются в problem JSON и не кэшируются.

Кэш матрицы использует отдельный `AudienceMatrix_v1_` + SHA-256 канонического JSON:
год, измерение, mapped фильтр с отсортированными distinct массивами и упорядоченный выбор колонок.
Null и [] различны, границы строк и пробелы сохраняются. Срок и память общие с прежним кэшем; перезапуск обновляет snapshot.
Прежние endpoints, их ключи кэша и игнорирование `UserFilter.year` не изменены.

## 🚢 Развёртывание

### CapRover

Production обновляется двумя независимыми механизмами:

- **Push-webhook CapRover на ветку `master`.** Любой push в `master`, включая merge pull request, запускает production-сборку на сервере. Поэтому не пушьте в `master` напрямую: изменения попадают туда только через pull request, а merge — это релиз.
- **`.github/workflows/deploy.yml`** запускается только вручную (`workflow_dispatch`): собирает образ, публикует его в GHCR и отправляет в CapRover.

`.github/workflows/verify.yml` проверяет каждый pull request (backend unit-тесты, фронтенд и `docker build`) и ничего не деплоит.

**Настройки CapRover:**
- Container HTTP Port: `29500`
- Environmental Variables:
  - `DEVRELAPP_CONFIG_DATABASE`
