# Решение о UI-библиотеке и графиках (issue #20)

**Решение:** остаётся RSuite 6, графики — Recharts 3. Воспроизводимого blocker нет: каждый провал проверки устранён документированным API либо принят по правилу исключений для автоматической проверки доступности (ниже). Резервный вариант — React 19 и Mantine 9 — не понадобился. Вторая UI-библиотека в проект не добавляется.

## Как проверяли

Проверка от 2026-11-07, системный Chrome, Playwright 1.65.

Для проверки собран временный vertical slice (в репозиторий не входит):
- шапка с разделами;
- «Год исследования» — `SegmentedControl`;
- семь полей фильтра — `CheckPicker` и `SelectPicker` с видимыми подписями;
- панель фильтров с черновиком — `Drawer` на ширине меньше 1224 px;
- карта — custom shape Recharts 3 с подсказкой `Whisper`;
- сортируемая таблица — `features/companies/CompanyTable.tsx`.

Slice работает на существующих `useSurveyState`, `useSurveyData` и `useFilterOptions`. Ответы API — синтетические, из `src/test/fixtures.ts`.

Критерии — §3.3 RFC в issue #20. Blocker — воспроизводимый провал критерия, который нельзя устранить документированным API или CSS-переменными.

### Нарушения axe

- **`aria-allowed-attr`**, critical. `Nav.Item` ставит `aria-selected` на элемент с `role="button"`.
  - Устранение: пропы пункта `aria-selected={undefined}` и `aria-current="page"` у активного.
  - Проверено: 0 нарушений на 1440 px.
- **`nested-interactive`**, serious, в открытом `CheckPicker`. Пункт `role="option"` содержит `<input type="checkbox" tabindex="0">`.
  - Пропа для замены нет: `renderCheckbox` есть только у `TagPicker`. У `TagPicker` другая подача — значения тегами — и та же проблема с фокусом.
  - Принято по правилу RFC: исключение с указанием причины в коде проверки доступности и в этом файле.
- **`aria-required-children`** (critical), **`aria-command-name`** и **`nested-interactive`** (serious) на 390 px, когда у таблицы своя горизонтальная полоса прокрутки. Элемент `role="scrollbar"` с ручкой `role="button"` без имени лежит внутри `role="grid"`.
  - Устранение без исключения: таблица шириной по содержимому внутри контейнера с `overflow-x: auto`. Получаем 0 нарушений; касание и фокус прокручивают таблицу, шапка совпадает с телом.
  - Цена: в этом режиме не работает закрепление колонки (`fixed`). Выбор между закреплённой колонкой «Компания» с исключением axe и нативной прокруткой делается в PR узкого экрана.
- Ограничение `rsuite-table`. После программной прокрутки таблицы (например, `scrollIntoView` заголовка) её собственная прокрутка касанием перестаёт работать. При нативной прокрутке этого нет.

Автоматическая проверка не доказывает соответствие WCAG; такого утверждения нет.

## Рецепты для следующих PR

Все устранения проверены в slice. В PR с RSuite 6 входит только п. 1: без него обновление ухудшило бы работу с клавиатуры по сравнению с `master`.

1. **Возврат фокуса после Escape и Tab** — `shared/usePickerFocusReturn.ts`.
   - Обёртка пикера с `display: contents` и `onKeyDown`: на Escape и Tab фокус переходит на `ref.current.target`.
   - Причина: RSuite 6 после закрытия вызывает `trigger.focus()`, а у объекта `OverlayTrigger` такого метода нет.
   - Применено к `MultiSelect`, «Посещает митапы» и выбору города на mobile.
   - Результат: Escape оставляет фокус в поле, Tab переводит его в следующее поле, как в RSuite 5.
2. **Поиск кириллицей**: `searchable={false}` и `renderListbox` с собственным `Input autoFocus`.
   - Enter открывает список с фокусом в поиске; «таг» оставляет «Таганрог».
   - Backspace в поле поиска не всплывает: иначе пикер очищает выбранное значение.
3. **«Выбрать все» с клавиатуры**: первый пункт `data` со служебным значением.
   - Отмечается стрелкой и Enter, как остальные пункты. Записывает весь список значений, повторное нажатие очищает.
   - Счётчик и подпись поля задаёт `renderValue`.
4. **Вложенный Escape в панели**: обёртка пикера запоминает в `onKeyDownCapture`, был ли список открыт (по `onOpen`/`onClose`), и в `onKeyDown` останавливает всплытие Escape, закрывшего список.
   - `Drawer keyboard={!listOpen}` не помогает: `onClose` списка синхронно обновляет состояние до того, как событие доходит до `document`.
   - Второй Escape закрывает панель, запросов 0.
5. **Навигация шапки**: `aria-current` вместо `aria-selected` у `Nav.Item`.
6. **Локаль**: `ruRU` с переопределением `common.remove` и `common.clear` («Удалить», «Очистить»).

Пункты 2 и 3 меняют вид «Выбрать все» и поведение поиска в списке относительно RFC. Решение о них принимается при проектировании PR с фильтрами.

## Что видно после обновления без редизайна

Функции интерфейса не меняются. Вид отличается в мелочах — это значения RSuite 6 по умолчанию; оболочку меняет следующий PR:
- у заголовка «В выборке N человек» другой размер и отступ — карта ниже примерно на 60 px;
- в боковой панели другие отступы и шевроны групп, ширина полей — 175 px вместо 184 px;
- выбранное значение в поле — цветом текста, а не акцента; у поля со значением вместо шеврона — крестик очистки;
- на ширине до 576 px включительно список открывается нижней панелью;
- над картой между флажками нет отступа: флажок вплотную к подписи предыдущего;
- у разделителей в «Составе выборки» меньше отступы.

Чтобы раскладка не сломалась, сделаны три правки.
- **`MultiSelect`**: добавлен `block`. Без него поле в RSuite 6 растёт по содержимому, не обрезает текст и наезжает на флажки над картой.
- **Recharts 3**: custom shape берёт `payload`, `cx`, `cy` из `ScatterPointItem`. Центры точек на тестовых данных совпали с Recharts 2 до пикселя.
- **`accessibilityLayer={false}` у всех графиков и `rootTabIndex={-1}` у `Pie`**: иначе Recharts 3 делает `<svg>` остановкой Tab с `role="application"`, а у `Pie` своя остановка Tab.
