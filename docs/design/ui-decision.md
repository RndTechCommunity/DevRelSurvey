# Решение о UI-библиотеке и графиках (issue #20)

**Решение:** остаётся RSuite 6, графики — Recharts 3. Воспроизводимого blocker нет: каждый провал проверки устранён документированным API либо принят по правилу исключений для автоматической проверки доступности (ниже). Резервный вариант — React 19 и Mantine 9 — не понадобился. Вторая UI-библиотека в проект не добавляется.

### Нарушения axe

- **`aria-allowed-attr`**, critical. `Nav.Item` ставит `aria-selected` на элемент с `role="button"`.
  - Устранение: пропы пункта `aria-selected={undefined}` и `aria-current="page"` у активного.
  - Проверено: 0 нарушений на 1440 px.
- **`nested-interactive`**, serious, в открытом `CheckPicker`. Пункт `role="option"` содержит `<input type="checkbox" tabindex="0">`.
  - Пропа для замены нет: `renderCheckbox` есть только у `TagPicker`. У `TagPicker` другая подача — значения тегами — и та же проблема с фокусом.
  - Принято по правилу RFC: исключение с указанием причины в коде проверки доступности и в этом файле.
- **`aria-required-children`** (critical), **`aria-command-name`** и **`nested-interactive`** (serious) на 390 px, когда у таблицы своя горизонтальная полоса прокрутки. Элемент `role="scrollbar"` с ручкой `role="button"` без имени лежит внутри `role="grid"`.
  - Устранение без исключения: таблица шириной по содержимому внутри контейнера с `overflow-x: auto`. Получаем 0 нарушений; касание и фокус прокручивают таблицу, шапка совпадает с телом.
  - Цена: в этом режиме не работает закрепление колонки (`fixed`). Выбор между закреплённой колонкой «Компания» с исключением axe и нативной прокруткой делается в PR узкого экрана.
- Ограничение `rsuite-table`. После программной прокрутки таблицы (например, `scrollIntoView` заголовка) её собственная прокрутка касанием перестаёт работать. При нативной прокрутке этого нет.

Автоматическая проверка не доказывает соответствие WCAG; такого утверждения нет.

## Рецепты для следующих PR

Все устранения проверены в slice. В PR с RSuite 6 входит только п. 1: без него обновление ухудшило бы работу с клавиатуры по сравнению с `master`.

1. **Возврат фокуса после Escape и Tab** — `shared/usePickerFocusReturn.ts`.
   - Обёртка пикера с `display: contents` и `onKeyDown`: на Escape и Tab фокус переходит на `ref.current.target`.
   - Причина: RSuite 6 после закрытия вызывает `trigger.focus()`, а у объекта `OverlayTrigger` такого метода нет.
   - Применено к `MultiSelect`, «Посещает митапы» и выбору города на mobile.
   - Результат: Escape оставляет фокус в поле, Tab переводит его в следующее поле, как в RSuite 5.
2. **Поиск кириллицей**: `searchable={false}` и `renderListbox` с собственным `Input autoFocus`.
   - Enter открывает список с фокусом в поиске; «таг» оставляет «Таганрог».
   - Backspace в поле поиска не всплывает: иначе пикер очищает выбранное значение.
3. **«Выбрать все» с клавиатуры**: первый пункт `data` со служебным значением.
   - Отмечается стрелкой и Enter, как остальные пункты. Записывает весь список значений, повторное нажатие очищает.
   - Счётчик и подпись поля задаёт `renderValue`.
4. **Вложенный Escape в панели**: обёртка пикера запоминает в `onKeyDownCapture`, был ли список открыт (по `onOpen`/`onClose`), и в `onKeyDown` останавливает всплытие Escape, закрывшего список.
   - `Drawer keyboard={!listOpen}` не помогает: `onClose` списка синхронно обновляет состояние до того, как событие доходит до `document`.
   - Второй Escape закрывает панель, запросов 0.
5. **Навигация шапки**: `aria-current` вместо `aria-selected` у `Nav.Item`.
6. **Локаль**: `ruRU` с переопределением `common.remove` и `common.clear` («Удалить», «Очистить»).

Пункты 2 и 3 меняют вид «Выбрать все» и поведение поиска в списке относительно RFC. Решение о них принимается при проектировании PR с фильтрами.

## Что видно после обновления без редизайна

Функции интерфейса не меняются. Вид отличается в мелочах — это значения RSuite 6 по умолчанию; оболочку меняет следующий PR:
- у заголовка «В выборке N человек» другой размер и отступ — карта ниже примерно на 60 px;
- в боковой панели другие отступы и шевроны групп, ширина полей — 175 px вместо 184 px;
- выбранное значение в поле — цветом текста, а не акцента; у поля со значением вместо шеврона — крестик очистки;
- на ширине до 576 px включительно список открывается нижней панелью;
- над картой между флажками нет отступа: флажок вплотную к подписи предыдущего;
- у разделителей в «Составе выборки» меньше отступы.

Чтобы интерфейс не изменился, сделаны три правки.
- **`MultiSelect`**: добавлен `block`. Без него поле в RSuite 6 растёт по содержимому, не обрезает текст и наезжает на флажки над картой.
- **Recharts 3**: custom shape берёт `payload`, `cx`, `cy` из `ScatterPointItem`. Центры точек на тестовых данных совпали с Recharts 2 до пикселя.
- **`accessibilityLayer={false}` у всех графиков и `rootTabIndex={-1}` у `Pie`**: иначе Recharts 3 делает `<svg>` остановкой Tab с `role="application"`, а у `Pie` своя остановка Tab.


## Проверка узкого экрана (PR5)

Обе таблицы используют HTML. Таблица компаний сохраняет семь колонок, сортировку по исходным значениям,
область высотой 500 px и шапку, закреплённую при вертикальной прокрутке. Обе оси прокручиваются нативно
(`overflow: auto`); закреплённых колонок нет (решение владельца PR5-TBL).

Проба RSuite Table с внешним `overflow-x: auto` сняла дефекты горизонтального scrollbar, но на 22 строках
собственный вертикальный scrollbar дал те же `aria-command-name`, `aria-required-children` и
`nested-interactive`. Публичного пропа для исправления его разметки нет. Нативная таблица устраняет обе
причины без исключений axe и позволяет браузеру пересчитывать высоты длинных названий после resize.
Состав выборки сохраняет сортировку, числа и полосы; на 390 px названия переносятся, полоса стоит под числом.

`e2e/a11y.spec.ts` сканирует страницы и фильтры на 390/1440 px. Единственное исключение — `nested-interactive`
у открытого CheckPicker: RSuite 6.2.5 вкладывает фокусируемый `input[type=checkbox]` внутрь `role=option`.
Публичного пропа для удаления этого вложения нет. Проверка оставляет правило включённым и допускает только
эти узлы внутри открытого множественного listbox; остальные правила и узлы проходят без исключений.

## Две темы (PR6)

Без сохранённого выбора сайт следует `prefers-color-scheme`, в том числе при изменении системной настройки
во время работы. Кнопка «Тёмная тема» в общей шапке переключает тему; её имя постоянно, `aria-pressed`
сообщает состояние, основной цвет кнопки обозначает включённую тёмную тему. Явный выбор сохраняется
в `localStorage['devrel-theme']` как `light` или `dark`. При ошибке чтения/записи используется системная тема.
Тема не входит в адрес исследования, не меняет группу/год/числа и не вызывает POST.

Цвета осей, сетки, обычной точки, полос и фокуса заданы в `tokens.css`. Там же скорректированы переменные
RSuite: в светлом списке прежний hover-текст давал 4,02:1, кнопка «Все участники» на фоне сообщения — 3,87:1;
белый текст тёмных сообщений info/error — 3,07/3,56:1. Фон основных кнопок и внутренний белый контур их
фокуса обеспечивают читаемость и при наведении/нажатии. Текст и поведение сообщений не меняются.

В проверке обеих тем обнаружена прежняя ошибка узкого состава: при вертикальной раскладке `share`
свойство `flex: 1` схлопывало дорожку и полосу до высоты 0. На ширине до 575 px дорожка теперь имеет
`flex: none`, сохраняет заданные 8 px и видна под числом. При нулевом знаменателе полосы по-прежнему нет.
Проверки размеров добавлены в существующие сценарии шести ширин и resize.

## Показатель, вид и таблица (PR7)

Для «Показателя» и «Вида» используется тот же SegmentedControl, что для года: подписанный radiogroup,
нативные radio и фокус на выбранном сегменте. На 390 px текст показателя переносится внутри трёх
горизонтальных сегментов; на coarse pointer каждое действие не меньше 44 px. После завершения CSS-перехода
индикатор совпадает с выбранной подписью: максимальное расхождение координат и размеров 0,469 px
для трёх показателей × двух тем × шести ширин. На 390 px — 0,344 px.

Карта получает доступное имя на самом SVG: год, показатель, число показанных компаний и отсылка
к виду «Таблица». Одновременно монтируется только одно представление. Фирменные цвета сохранены; поведение единственной подписи обновлено в PR8 (ниже).

Таблица компаний теперь занимает высоту своих строк. Обычный `position: sticky` внутри `overflow-x: auto`
не закрепляет шапку относительно документа. Вместо копии заголовков единственный `thead` сдвигается по Y
в пределах таблицы, оставаясь в том же горизонтальном контейнере. Scroll/resize и ResizeObserver обновляют
смещение; useLayoutEffect пересчитывает его до paint при смене строк, чтобы старое смещение не создавало
вертикальную прокрутку у короткого года. У слушателей и observer есть cleanup, нового состояния React нет.

Проверено в Chrome 156.0.8078.80 на синтетических данных: обе темы × 390/768/1223/1224/1225/1440,
верх шапки при прокрутке 0 px, внутреннее вертикальное переполнение 0 px. Регрессия в `baseline.spec.ts`
проверяет 27 строк, настоящий touch, совпадение колонок, конец таблицы, resize, сортировку Enter и смену
года/вида. Axe проверяет оба представления в двух темах на 390/1440; прежнее исключение CheckPicker
сохранено без расширения. Проверка не заявляет полного соответствия WCAG.


## Поиск и подпись компании (PR8)

Поиск использует SelectPicker с тем же usePickerFocusReturn и responsive=false, что другие списки.
При открытии onEntered фокусирует встроенный поиск через публичный PickerHandle.overlay; существующая
проверка открытости не допускает позднего перевода фокуса после Escape. Клавиатурный ввод кириллицы,
выбор, очистка, Escape и Tab проверяются на 390/1440 в обеих темах. Поиск не меняет список строк,
URL и API-запросы. Выделенная строка сохраняет обычный цвет текста и получает фон списка и контур.

Точка 4 px обведена цветом текста темы. Найденная точка — 7 px с кольцом 10 px, рисуется последней.
Единственная подпись сохраняет фирменную заливку и обводится цветом текста темы (1,5 px,
paint-order: stroke, 600/12 px). Штатные Text/usePlotArea переносят длинное имя в доступную сторону
карты без отдельного состояния размеров. Имя в подсказке исходное; числовые строки не переносятся.

Проверено на плотных синтетических данных (40 компаний): обе темы × 390/768/1223/1224/1225/1440.
Границы длинных подписей при 0 % и 100 % узнаваемости остаются внутри карты, текст — внутри
горизонтальных границ области построения. Контраст обводки к фону: 12,45:1 / 15,60:1;
обычного цвета точки и подписи: 7,00:1 / 9,38:1. Текст выделенной строки: 11,10:1 / 8,87:1
(светлая / тёмная). Полупрозрачный фон строки измерен после наложения на фон страницы.
Фирменные заливки сами по себе могут иметь низкий контраст; читаемость обеспечивает согласованный
контур. Снимки «Тинькофф» в светлой и «Почтатех» в тёмной теме просмотрены вручную.
Axe не доказывает контраст SVG-текста; полное соответствие WCAG этой проверкой не заявляется.
